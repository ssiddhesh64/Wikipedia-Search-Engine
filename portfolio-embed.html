End-to-End Search Engine Pipeline

Designed for sub-millisecond retrieval without exhausting RAM on multi-gigabyte corpora.

1
Batch Ingestion

Streams articles from SQLite in chunks of 1,000 to prevent OOM errors on large 21GB database files.

2
Binary Serialization

Packs postings lists into raw binary structs (uint32) and records byte offsets in a compact vocabulary map.

3
O(1) Seek Retrieval

Given query tokens, the engine seeks directly to byte offsets in postings.bin, scoring candidates in microseconds.

// Okapi BM25 Ranking Formula
Score(D, Q) = ∑ IDF(q) * [ tf * (k1 + 1) ] / [ tf + k1 * (1 - b + b * (|D| / avgdl)) ]
k1 = 1.5 (term saturation), b = 0.75 (document length penalty), avgdl = average corpus length

Binary Disk Layout (postings.bin)

Each token in vocab.pkl maps to a byte offset pointing to this packed binary block:

[Offset: vocab[token]]
0x00: num_docs (uint32, 4 bytes) - Number of documents containing token
For each document:
├── doc_id (uint32, 4 bytes)
├── term_frequency (uint32, 4 bytes)
├── positions_count (uint32, 4 bytes)
└── positions[tf] (list of uint32, tf * 4 bytes)
💡 Performance Advantage: Unlike JSON or SQLite string matching, binary struct seeks bypass deserialization overhead, enabling single-digit millisecond response times even under high query concurrency.
